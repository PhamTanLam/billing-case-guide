プラン

管理者は画面プラン管理（マスタ）でプランを作成します。各プランには3つのサイクルの価格、プロジェクト / ストレージ / AI利用量の上限、メンバー上限、初月割引（%）、そしてアップグレードとダウングレードを判定するランクがあります。プランは法人と個人で共通で、分かれていません。単価は1シートあたりです：期間の料金 = シート数 × そのサイクルの単価。個人アカウントは常に1シートのため、期間の料金は単価と同額になります。

追加プラン

料金の計算方法メインプラン（管理者が月・四半期・年の価格を入力）と異なり、追加プランには1日あたりの価格が1つのみで、請求はすべて日額 × 日数です。1法人のすべての追加プランは共通の次回支払日を使います。初回登録時、テナントは新期間の開始日を選びます。初回期間（本日からその日まで）は日割りで支払い：今期のお支払い ¥{日額} × {日数}日。その日以降、定期更新をオンにすると1か月ごとに更新され、各期間の料金 = 日額 × その期間の日数（計算式）。

毎月の支払い

  • 初回期間の請求、追加プランの請求、更新の請求はいずれも支払い履歴に行が追加されます。支払日は請求時点で記録されます。
  • 各更新期間は日額 × その期間の日数を請求。次回更新時の日数は支払い成功のたびに事前に算出されます。
  • 最初の更新請求に失敗 → 追加プランは支払い遅延となり、通常プランと同様に再請求が予定されます。
  • 期間終了時に更新しない → すべての追加プランが終了し、表示されなくなります。

使用済み額とクレジット（月 → 四半期 → 年の段階計算）

期間途中でアップグレードする場合、使用済み額は期間全体で均等に割るのではなく、価格の段階で計算します：1か月目は月額、2〜3か月目は四半期価格 − 月額の差額、4〜12か月目は年額 − 四半期価格の差額。各区間はその区間の実日数で均等に割ります。

区間1（1か月目） ：日額 = 月額 / 1か月目の日数 区間2（2〜3か月目）：日額 = (四半期価格 − 月額) / 2〜3か月目の日数 区間3（4〜12か月目）：日額 = (年額 − 四半期価格) / 4〜12か月目の日数 使用済み額 = Σ 日額 × 区間内の利用日数 （上限 = 現在のサイクルの価格） 支払済み額 = 今期の直近の「成功」支払い クレジット = max(0, 支払済み額 − 使用済み額) 即時請求額 = max(0, 新プラン料金 − クレジット)

Stripeに送るphaseパラメータ既存のScheduleを更新する場合、phase 1には次が必須：start_date；phase 2では次を使用：end_date＝phase 1の終了＋新サイクルの月数。次は使わない：duration（Stripe API 2026-05-27はどちらの場合も拒否）。

Stripe上の追加プラン

  • unitPrice（価格行の）ADD_ONは1日あたりの価格。プランのStripe Price＝1日の価格；quantity（subscription itemの）＝期間の日数。
  • 1テナントのすべての追加プランで1つのStripe Subscriptionを共用。初回期間：subscription itemは¥0のPrice＋1回限りの請求（add_invoice_items、日額 × 日数）、proration_behavior=none。
  • 自動更新オン：subscriptionからScheduleを作成、end_behavior=release；phase 1は新期間開始日まで¥0のPrice、phase 2は日額のPriceでquantity＝期間の日数、phase開始時点で請求サイクルを固定、1か月実行。自動更新オフ：Scheduleなし、次を設定：cancel_at＝その日。
  • 追加プランsubscriptionの支払い成功webhookのたびに：BullMQジョブが次回更新時の日数を計算し、更新継続中のすべてのitemのquantityを更新、proration_behavior=none、リトライあり。quantityは、Stripeが更新invoiceを作成する前に必ず用意される；ジョブを再実行してもデータは壊れない。
  • Stripe Price未作成のプラン：プランのProduct配下に日額のPriceと¥0のPriceを作成し、現行の価格スケジュール行に保存。
  • 追加登録：1回のsubscription更新でitem追加、1回限りの請求の添付（add_invoice_items＝残り日数 × 日額、BEで計算）、即時請求を同時に実行；payment_behavior=error_if_incomplete。カード拒否時はStripeが更新全体を取り消し、itemやinvoice itemは残らない。Scheduleの修正が必要な場合はこの更新が成功した後に行う。初回期間でScheduleあり：両方のphaseに追加；初回期間で自動更新オフ：¥0 Priceのitemのみ追加；新期間開始日以降：日額Priceのitemを追加。
  • 自動更新オフ：初回期間でScheduleあり → releaseしてから次を設定：cancel_at；新期間開始日以降でScheduleが紐づいている → Schedule経由で解約；Scheduleがrelease済み →cancel_at＝期間終了。再度オン：次を解除cancel_at、初回期間ならScheduleを2 phaseで再作成；Scheduleが解約待ち → 次を再設定：end_behavior=release。
  • 1プランの更新解除：そのプランの日額Priceを次回更新時phaseから即時に削除（ジョブ経由ではない）、item →PENDING_CANCEL。最後のプラン：Scheduleをreleaseしてから次を設定：cancel_at、または次を設定：cancel_at（直接、基準：current_period_end、Scheduleがない場合はStripeからリアルタイムに取得）。
  • プランの再登録PENDING_CANCEL：subscription item idを維持し、日額Priceを次回更新時phaseに再追加。最後のプラン：初回期間なら次を解除cancel_atしてからScheduleを2 phaseで再作成；新期間開始日以降はScheduleを再設定end_behavior=release。
  • 価格変更：更新phaseの日額Priceのみ差し替え、現在のitemは変えない；Scheduleがrelease済みなら次回更新からitemのPriceを変更、日割りなし。

管理者による価格変更・プラン終了

  • 1プラン＝1 Stripe Product；すべてのStripe Price（サイクルごと、価格変更ごと）は同じProductに紐づく。Productはプラン名で1回だけ作成；Priceがすでにある価格行は再利用。
  • 適用日Tのプラン価格変更：T−2に親ジョブが新しい価格行のStripe Priceを登録（未作成なら）し、次回更新時にそのプランを使う各テナントごとに子ジョブを1つ作成。子ジョブはScheduleを作成/更新：旧価格は次まで維持currentPeriodEnd、その後は新価格（ただしTより前にはならない）；移行予約で入ってくるテナントは将来のphaseのみ修正。
  • プラン終了：3サイクルすべてにINACTIVEのスケジュールを作成；メールジョブはT−14まで、subscription更新ジョブはT−2まで遅延；価格変更パイプラインは実行しない。利用中のテナント：期間末の解約を設定、Scheduleがあれば経由（進行中のphaseは維持、新価格のphaseは削除）。

  • プラン価格変更メールのfan-outジョブ（PlanPriceChangeMailNoticeFanOutProcessorService）はT−14に実行：プラン利用中の各テナントのownerに送信、ジョブは次へ遷移：DONE。ジョブ実行前に管理者がさらに新しい価格に変更していた場合 → 送信せず、ジョブは次へ遷移：PLAN_CHANGED。プラン終了/追加プランのメールジョブも同様に「スケジュール変更済み」ステータスを使用。

    • 送信エラー → 行を記録：FAILED（エラー内容付き）、エラーを外に投げてBullMQにリトライさせる。
    • すでに次の行がある：SENT→ スキップ、再送しない、新しい行も作らない。
    • 次の行のみある：FAILED→ 再処理し、新しい行を作成。
  • Stripeのメール（STR-01…07）は次を経由しない：MailJob。受信者はStripe customerのemailで、1回だけ設定される場所：StripeService.createCustomer（payloadには次のみ：email、name、test_clock；次はない：preferred_locales）。customers.updateは現在、次の変更にのみ使用：invoice_settings.default_payment_method、emailは更新しない。

換算と入力データ

3サイクルの価格

管理画面では3サイクルの絶対価格を入力し、FEがサイクルごとの割引率に換算してBEへ送信（quarterlyDiscountPercent/yearlyDiscountPercent）。BEは3行を保存PlanPricingSchedule（計算式）：

月額 ＝ 元の月額 四半期 ＝ 元の月額 × 3 × (1 − 四半期割引率) 年額 ＝ 元の月額 × 12 × (1 − 年割引率)

例：1,000/月、四半期割引10%、年割引20% → 1,000 / 2,700 / 9,600。

日次でリセットされる上限（LIM-04）

TenantResourceLimitが本日中に更新済み → 値をそのまま返し、再計算しない。昨日以前のレコード → 現在のプランで再計算。追加プランを登録した場合は即時再計算。

不正な入力データ

BillingCoreServiceがエラーを投げる条件：価格段階リストが空；billingCycle ≤ 0 またはどの段階にも一致しない；価格または支払済み額がマイナス；期間開始日が未来；利用日数が期間の総日数を超える；levelが数値でない；新プラン価格またはcreditがマイナス。

キーワードに一致するケースがありません。エラーコード（例：PAST_DUE）や別のキーワードでお試しください。
